# Security Policy

## Supported Versions

Security fixes are handled on the active development line and are released from
the current default branch after validation.

## Reporting A Vulnerability

Use GitHub private vulnerability reporting for this repository when available.
If private reporting is unavailable, open a minimal GitHub issue without exploit
details and request a private coordination channel.

Please include:

- Affected version, branch, or commit.
- Reproduction steps with the smallest safe example.
- Expected and observed behavior.
- Impact and whether credentials, local files, or user data are involved.

Do not publish working exploits, secrets, private data, or destructive proof of
concepts in public issues.

## Response

Reports are triaged by severity. Confirmed vulnerabilities are fixed with the
smallest safe patch, validated locally, and documented in the release notes when
appropriate.
